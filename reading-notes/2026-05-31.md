# [在浏览器输入 URL 后会发生什么？](../translations/zh/what-happens-when-you-type-a-url-into-your-browser.zh.md)

阅读时间：2026-05-31

## 问题 1：URL 最前面的 `scheme` 是什么？可以叫 `schema` 吗？

**参考答案：** URL 最前面的部分更准确地叫 **URL scheme**，中文可译为“协议方案”。它告诉客户端应该用什么规则或协议来处理这个地址。

```text
https://example.com/product/electric/phone
^^^^^
scheme
```

常见的 scheme 包括：

- `http://`：普通 HTTP
- `https://`：加密 HTTP，网页最常见
- `file://`：本地文件
- `ftp://`：FTP 文件传输
- `mailto:`：打开邮件客户端
- `ws://`：WebSocket
- `wss://`：加密 WebSocket
- `data:`：把数据直接写在 URL 里
- `blob:`：浏览器内生成的临时对象 URL
- `tel:`：电话号码链接
- `ssh://`：SSH 连接地址

`schema` 不是这里的标准叫法，学习 URL 组成时应使用 `scheme`。

## 问题 2：URL 里的 `path` 和文章中提到的 `resource` 是什么关系？

**参考答案：** 严格从 URL 标准来说，`resource` 不是 URL 的固定组成部分；文章为了教学，把路径里的最后一段单独叫作“资源”。

```text
https://example.com/product/electric/phone
                    ^^^^^^^^^^^^^^^^^^^^^^
                    path
```

整体 `/product/electric/phone` 都属于 **path**。

如果按文章的拆法，可以这样理解：

```text
/product/electric/phone
 ^^^^^^^^^^^^^^^^^ ^^^^^
 path              resource
```

- `path`：资源所在的位置或目录路径，比如 `/product/electric`
- `resource`：最终想访问的东西，比如 `phone`

真实 Web 系统里，URL path 不一定对应服务器上的真实文件路径，它可能只是路由规则。服务器可以把 `/product/electric/phone` 解释成一个 HTML 页面、一个 API 资源、一个商品详情页、数据库里的一条记录，或者前端 SPA 的路由。

# [在浏览器输入 google.com 后会发生什么？](../translations/zh/what-happens-when-you-type-google.zh.md)

阅读时间：2026-05-31

## 问题 1：TLD nameserver 是什么？Authoritative Nameserver 是什么？

**参考答案：** 在 DNS 查询里，可以把它理解成一层层问路。

**TLD nameserver** 是“顶级域名服务器”，负责 `.com`、`.org`、`.net`、`.cn` 这类顶级域。比如查 `google.com` 时，根 DNS 服务器会告诉递归解析器：`.com` 归这些 TLD nameserver 管，应该去问它们。

但 TLD nameserver 通常不会直接返回 `google.com` 的 IP 地址，而是告诉解析器：负责 `google.com` 这个具体域名的权威 DNS 服务器是谁。

**Authoritative Nameserver** 是“权威域名服务器”，它真正掌握某个具体域名的 DNS 记录，比如 `google.com` 的 A 记录、AAAA 记录、MX 记录等。递归 DNS 解析器最后会问它：`google.com` 的 IP 是多少？它返回最终答案。

查询链路可以简化为：

```text
浏览器想访问 google.com
-> 问递归 DNS 解析器
-> 递归解析器问根 DNS：谁管 .com？
-> 根 DNS 返回 .com 的 TLD nameserver
-> 问 .com TLD nameserver：谁管 google.com？
-> TLD nameserver 返回 google.com 的 authoritative nameserver
-> 问 authoritative nameserver：google.com 的 IP 是多少？
-> 返回 IP 地址
```

一句话总结：TLD nameserver 负责告诉你“这个域名该去问哪个权威服务器”；Authoritative Nameserver 负责给出“这个域名最终对应什么记录/IP”。

## 问题 2：DOM 树和 CSSOM 树是什么？

**参考答案：** 浏览器会把 HTML 文档解析成 **DOM 树**，也就是页面结构树。DOM 描述页面里有哪些节点，以及这些节点之间的父子关系，例如 `html`、`body`、`h1`、`p` 等元素。JavaScript 中的 `document.querySelector()`、`appendChild()` 等 API 操作的就是 DOM。

浏览器也会把 CSS 解析成 **CSSOM 树**，也就是样式规则树。CSSOM 描述不同元素应该应用哪些样式，例如颜色、字体大小、布局属性等。

一句话总结：

```text
DOM：页面有哪些元素，以及元素之间的结构关系
CSSOM：这些元素应该应用什么样式
```

## 问题 3：JavaScript 的分词器、解析器、渲染树是什么？

**参考答案：** **分词器 tokenizer** 会把源代码文本切成一个个有意义的小片段，叫 token。例如 `let x = 1 + 2;` 会被切成 `let`、`x`、`=`、`1`、`+`、`2`、`;` 等 token。

**解析器 parser** 会把 token 进一步组织成语法结构。对 JavaScript 来说，解析器会生成 **AST（抽象语法树）**，之后 JavaScript 引擎再把它编译成字节码或机器码并执行。

需要特别区分：**渲染树不是 JS 的东西**，它不是 JavaScript 解析器生成的。渲染树是浏览器渲染引擎结合 **DOM 树 + CSSOM 树** 后生成的，表示页面上真正需要绘制出来的节点。

流程可以简化为：

```text
HTML -> 分词/解析 -> DOM 树
CSS  -> 分词/解析 -> CSSOM 树
DOM + CSSOM -> 渲染树
渲染树 -> 布局 -> 绘制 -> 显示到屏幕
```

JavaScript 的作用是执行脚本；如果脚本修改了 DOM 或样式，浏览器可能需要重新生成或更新渲染树，并重新布局、绘制页面。
