上图展示了缓存系统常见的 4 种失效场景，以及相应的解决思路。

## 1. 惊群问题（Thunder Herd Problem）

当大量缓存 key 在同一时间过期时，就会出现这个问题。此时大量查询请求会直接打到数据库上，从而把数据库压垮。

缓解这个问题有两种常见方式：一种是不要给所有 key 设定完全相同的过期时间，可以在配置中加入随机值；另一种是只允许核心业务数据访问数据库，而在缓存恢复之前，阻止非核心数据继续访问数据库。

## 2. 缓存穿透（Cache Penetration）

当某个 key 在缓存里不存在，在数据库里也不存在时，就会出现这个问题。应用无法从数据库中取到对应数据来回填缓存，于是会持续对缓存和数据库都造成压力。

解决它通常有两个办法：

* 对不存在的 key 也缓存一个空值，避免反复打到数据库。
* 先用布隆过滤器检查 key 是否可能存在；如果布隆过滤器已经判断它不存在，就可以直接避免访问数据库。

## 3. 缓存击穿（Cache Breakdown）

这个问题和惊群问题很像，只不过它发生在某个热点 key 过期的时候。由于大量请求都集中访问这个热点 key，它一失效，就会有大批请求直接打到数据库。

既然热点 key 通常承担了 80% 的查询量，那么对这些热点 key，往往就不应该设置过期时间。

## 4. 缓存宕机（Cache Crash）

当缓存整体不可用时，所有请求都会转而访问数据库。

解决这个问题有两种常见方式：

* 使用熔断器。当缓存挂掉时，应用服务既不能访问缓存，也不能继续直接打数据库。
* 为缓存搭建集群，提高缓存本身的可用性。
